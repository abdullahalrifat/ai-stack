# AI Stack v0.8 — Autonomous Engineering Runtime

v0.8 turns cloud-worker leases into a fenced execution protocol and makes Server the durable authority for attempt ownership, cancellation, proof and idempotent submission. The v0.8.1 audit fixes release dependency drift, tagged image publication and Postgres gate coverage.

## Completion and proof gate

A successful cloud attempt may publish its result only while holding the
current unexpired lease, after transitioning through `uploading_result`, and
with a non-empty durable proof. Premature, proofless, stale, or cancelled
completion writes are rejected. Failed attempts may still publish bounded
diagnostics from an active fenced state.

## Cloud task lifecycle

The normal path is:

`queued → leased → preparing_workspace → running → verifying → uploading_result → completed`

Failure/cancellation states remain durable. Worker-driven transitions require the current unexpired lease fence.

## Lease fencing

Every claim generates a fresh UUID `lease_id` and increments `attempts`. Heartbeat, state updates and completion require task ID, worker ID, current lease ID and an unexpired lease.

After expiry/reclaim, an old worker cannot renew or publish completion. Cancellation clears the fence and is terminal.

Fencing protects durable ownership; it is not a substitute for process/container isolation on a shared worker host.

## Idempotency

`POST /platform/cloud/tasks` accepts `idempotency_key`. A partial unique index guarantees concurrent retries with the same key resolve to one durable task. Reusing a key with a different task payload is rejected.

Clients should generate one stable key for one logical submission and reuse it only across transport retries.

## Portable Git workspaces

A task references either an allowed existing workspace or an HTTPS Git repository with optional safe ref/exact commit. The worker revalidates URL/ref/commit, checks `JARVIS_CLOUD_GIT_ALLOW_HOSTS`, creates an ephemeral checkout and returns bounded tracked/untracked patch metadata.

Repository URLs cannot embed credentials. Worker Git credentials remain worker-local.

## Model selection and secrets

Cloud payloads carry only model/profile selectors, never provider credentials. `auto` uses worker-local calibration. Named profiles resolve provider/endpoint/capabilities/API-key environment on the worker, and provider switches cannot reuse another provider's API key.

## Execution proof

Server stores worker proof on the cloud task. Proof contains lease/workspace/route/execution/verification/result evidence; it is not model chain-of-thought.

For production, proof/event retention and audit export policy still need explicit operator configuration and lifecycle controls.

## Cron schedules

Schedules use conventional five-field UTC cron semantics with lists/ranges/steps, Sunday `0/7`, and DOM/DOW OR semantics when both fields are restricted.

## Isolation boundary

The current external worker is designed for trusted self-hosted/single-tenant execution. A world-class multi-tenant deployment still requires a fresh constrained task sandbox with:

- CPU/RAM/PID/disk quotas;
- seccomp/AppArmor or equivalent host policy;
- explicit writable/read-only mounts;
- policy-controlled network egress;
- credential minimization;
- deterministic environment bootstrap;
- safe content-addressed/cache identity and invalidation.

Do not infer multi-tenant containment from lease fencing alone.

## Required validation

A production release must execute coverage for:

- concurrent idempotent submission and payload mismatch;
- wrong-worker/wrong-fence heartbeat/state/completion rejection;
- expired-fence completion rejection and task reclaim with a new fence;
- terminal cancellation and non-reclaimability;
- valid/invalid execution-state transitions;
- Postgres migration from the previous schema;
- worker and Server restart/network-partition/cancellation races;
- cross-repository CLI/Core/Server/Postgres behavior;
- supply-chain image/SBOM flow;
- real Ollama/LiteLLM native tool integration;
- prompt-injection/secret-canary and long-running chaos/soak cases.
